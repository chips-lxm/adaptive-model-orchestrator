# 宿主与推理档位

普通子智能体统一使用 `gpt-6.2-sol`。主会话保留用户选择的配置。

| 档位 | 选择条件 |
| --- | --- |
| `medium` | 规则、输入和职责明确，风险低，结果可直接核对。例如按既定清单校验文件或整理已给材料。 |
| `high` | 默认档位。适用于常规分析、实现、集成、审查和独立验收。 |
| `xhigh` | 有明确难点，例如复杂依赖、难定位根因、重要跨模块逻辑或需要深入验证。 |
| `max` | 对交付或高风险验收起决定作用、确实需要困难推理的核心判断或实现。 |

按当前难点直接选择档位。任务长度、涉及文件数量和空闲并发额度都无法单独说明需要提高档位。出现失败时，先检查原因和受影响范围，再按 [升级与返工](collaboration-and-validation.md#升级与返工) 处理。

## 派发方式

对照当前工具声明、可获取的模型目录和实际调用证据确认宿主支持。目录缓存缺项时以当前工具声明与实测为准。先确认 `collaboration.spawn_agent` 支持的参数和并发限制，再选择派发方式。

- **继承历史和配置**：分支确实需要前序对话，而且父会话的实际模型和档位已确认符合该分支配置时，使用 `fork_turns: "all"`，省略模型和推理档位参数。
- **指定配置**：其余情况使用 `fork_turns: "none"`，在结构化参数中传入 `model: "gpt-6.2-sol"` 和选定的 `reasoning_effort`。消息提供必要用户原话、后续纠正、原始材料入口、修改边界和验收条件。若无法完整交接影响判断的上下文，由主会话处理这部分。

全历史派发继承父会话配置。只有结构化配置或宿主提供的可验证机制能设置子智能体的模型和档位。无历史派发和磁盘访问权限是独立的宿主能力；按已授权范围划定读写边界。

需要为正在处理的工作提高档位时，先确认宿主能否重配现有分支。若只能派发新分支，先结束原执行者的修改职责，再把原始要求、证据和尝试结果交给新负责人。

## 生效证据

按需记录派发方式、请求的模型与档位、工具结果和可取得的实际模型与档位。以宿主回显、运行元数据或明确的工具契约标记证据来源；工具接受参数但未回显实际配置时，记录可确认的请求与契约，把未能独立确认的字段标为未知。子智能体自述不用于核实其配置。

宿主不能按所需配置派发时，由主会话推进其可完成的工作，说明受影响的委派和验证范围。保留已取得的证据和原有验收条件；需要指定配置或独立验收而实际无法完成的部分，按受限交付报告。
