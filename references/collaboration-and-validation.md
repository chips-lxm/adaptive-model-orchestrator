# 协作与验收细则

只在任务实际需要时读取本文件。这里补充角色分工、分支交接、状态和升级规则。

## 典型职责

| 工作 | 默认配置 | 适用范围 |
|---|---|---|
| 理解需求与整理限制 | 当前主会话；有独立整理收益时 Sol · medium | 提取目标、材料、约束、交付格式与验收要求；不重复委派主会话已完成的理解 |
| 复杂任务整体方案 | Astra · high | 确定核心方法、任务结构、依赖和验收标准 |
| 搜集与整理资料 | Luna · high；复杂材料用 Sol · medium/high | 规则明确时检索、提取、分类并保留来源；来源冲突或关键解释交 Sol |
| 分工与进度协调 | Sol · medium | 派发任务、跟踪状态、处理依赖；方案冲突返回 Astra |
| 代码与文件制作 | Sol · medium/high | 实现、制作并运行必要验证；明确深入推理需要可用 xhigh |
| 内容表达与结构设计 | Sol · medium/high | 组织讲解逻辑、叙事和视觉层级 |
| 机械排版与批量修改 | Luna · high；复杂布局用 Sol · medium/high | 套用既定样式并检查渲染效果；少量修改不自动等于低风险 |
| 常规检查与修正 | Sol · high 审查；原执行模型修正 | 检查遗漏、报错、格式、引用与接口并定点修复 |
| 复杂任务最终验收 | Astra · medium；复杂逻辑用 high | 对照原始要求、实际成品和关键验证证据 |

这些是路由默认值，不要求每个任务执行全部步骤或为每个角色新建分支。角色可以合并，主智能体可同时承担执行与协调职责；即使是复杂任务，也仅在独立审查的预期收益超过交接与协调成本时另设验收分支。

本表 Astra、Sol、Luna 分别指 `gpt-6-astra`、`gpt-6-sol`、`gpt-6-luna`。需要独立审查时，角色合并不能取消执行者与验收者分离；两个角色使用相同模型也应由不同智能体承担。Luna 固定 high；需要超出其任务边界的推理时交 Sol 或 Astra，不用反复提高 Luna 档位代替升级。

## 分支派发与返回

派发时说明：

- 任务目标与可核对的验收标准；
- 必要原始材料、约束和来源入口；
- 可修改范围及明确边界；
- 前置依赖、接口约定与完成后的接收方。

要求分支返回：

- 实际产物、文件位置或可直接集成的结果；
- 验证方法、结果和证据；
- 未解决问题、失败证据及影响范围；
- 需要总负责人决定的事项与备选方案。

总负责人维护简洁任务清单，至少记录目标、负责人、实际模型与强度、依赖、产物位置和验证状态，并纳入主智能体自己的工作。环境未提供的模型或强度标为未知，不将请求配置当作已确认的实际配置。状态使用：待开始、进行中、等待依赖、待检查、已完成、受阻。

## 就绪与结果接收

- 派发执行任务前，确认所需输入和接口已足够稳定、修改范围无冲突且有可用并发额度。同属一个业务模块不自动意味着修改冲突，应按明确文件或共享产物判断。共同依赖可先由一个负责人确定最小接口约定，再并行推进实现；不必等待无关部分全部完成。
- 收到消息或看到中间文件不等于前置产物已就绪。用于后续执行的产物需有明确位置与适用版本，并通过该后续任务所需的检查；若分支仍在修改它，先约定稳定交付点，避免依赖半成品或过时内容。审查进行中的工作时明确审查版本，结论仅适用于该版本。
- 等待期间发生要求变更、分支失败或依赖解除时，重新判断可推进的工作。分支超时或失败先检查状态与原因，不仅因耗时较长就复制同一任务；确需接管或重派时，先停止原执行并交接已有成果与修改权限。无法自行取得必要外部输入时，说明缺失信息及其影响，按任务约定等待或交付当前进展，避免连续有界等待变成无期限轮询。
- 按结果影响范围安排检查：局部完成先核对接口与相关行为，整体集成后再对照原始要求验收；核心逻辑或接口变化时重新检查受影响的依赖任务。

## 升级与返工

| 障碍 | 动作 |
|---|---|
| 缺少信息或证据 | 补充读取或检索；无法取得的必要信息标为受阻 |
| 工具或环境问题 | 检查输入、权限、依赖和日志，不盲目提高推理强度 |
| 明确的推理困难 | 直接提高强度或升级至合适模型，无需机械地逐级尝试 |
| 同一问题定点修正后仍失败 | 携带原始要求、失败证据和已尝试方法升级，避免重复尝试 |
| 核心方案错误 | 由 Astra 修改相关方案，标记受影响产物并通知对应分支 |
| 局部内容或格式错误 | 原执行模型定点修复，并复查修改部分及受影响依赖 |

审查意见必须包含具体位置、证据、影响和修改要求。纯风格偏好不自动触发整份重写。常规审查优先路由至 Sol，复杂验收优先路由至 Astra，仍按上述角色合并与分支收益原则执行；修改关键含义、核心逻辑或整体方案后必须重新验收。
