# 协作与验收细则

只在任务实际需要时读取本文件。这里补充角色分工、分支交接、状态和升级规则。

## 典型职责

- 主会话负责理解需求、跟踪依赖、接收结果和整体验收，也可直接执行边界明确的工作。
- 可独立委派的工作包括按来源整理资料、实现、内容与结构设计、定点修正和验收。方案或证据出现冲突时，由掌握足够原始材料的负责人解决，并核对结论对其他任务的影响。
- 评估独立审查的收益时，考虑误判后果、所需独立性和交接成本。需要独立审查时，审查者不得参与本项修改。

按 [宿主与推理档位](runtime.md) 为每个值得委派的任务选配置。

## 本轮规则与证据

长任务、多分支或安装可能更新时，在已有运行证据目录或临时目录创建一次规则快照：

```sh
python3 scripts/freeze_run.py --output /绝对路径/本轮证据/skill-snapshot
```

脚本输出快照入口与内容摘要，包含运行所需正文、参考、脚本、配置、示例、说明和素材；排除 Git、项目维护文档与历史测试。选 Codex 不会自动发现的目录，不在任何 skills 安装目录内创建副本。快照应保留至本轮结束；续答、后续分支和升级任务读取快照内路径，不能悄悄回到全局安装路径。记录摘要不能替代实际固定文件。校验使用 `python3 scripts/freeze_run.py --verify /绝对路径/skill-snapshot`；缺失或不一致时先恢复原快照或明确版本变更并重核对受影响工作。

本轮目标、用户原话、约束、材料清单及基准只维护一次。分支引用这份记录，补充自身范围、依赖、验收及必要原文，不反复复制完整聊天。共享原始事实和日志；需要独立首轮判断时不提前共享其他审查者结论。重要判断始终保留原始材料入口。

证据仅在成果内容、需求、依赖、配置、环境和输入仍适用时复用；时间敏感的外部事实重新核实。失效范围不清时扩大必要检查。同一问题的日志引用一次，返回结论、位置、结果和未解决事项；原始失败证据保留可读路径。独立验收者必须亲自执行关键检查，不能把修复者的通过记录当作独立验收。

性能评估按本轮主会话及所有分支的实际增量记录输入、缓存、输出、耗时和返工；推理 token 若已计入输出不再重复相加，累计快照不重复求和。无可靠统计时标为未测，不由文本字数推算 token 收益。

## 分支派发与返回

派发时说明：

- 任务目标与可核对的验收标准；
- 本轮规则快照、基准及必要原始材料、约束和来源入口；
- 可修改范围及明确边界；
- 前置依赖、接口约定与完成后的接收方。

要求分支返回：

- 实际产物、文件位置或可直接集成的结果；
- 验证方法、结果和证据；
- 未解决问题、失败证据及影响范围；
- 需要总负责人决定的事项与备选方案。

总负责人维护简洁任务清单，至少记录目标、负责人、实际模型与强度、依赖、产物位置和验证状态，并纳入主智能体自己的工作。环境未提供的模型或强度标为未知，不将请求配置当作已确认的实际配置。状态使用：待开始、进行中、等待依赖、待检查、已完成、受阻。

## 就绪与结果接收

- 派发执行任务前，确认所需输入和接口已足够稳定、修改范围无冲突且有可用并发额度。同属一个业务模块不自动意味着修改冲突，应按明确文件或共享产物判断。共同依赖可先由一个负责人确定最小接口约定，再并行推进实现；不必等待无关部分全部完成。
- 收到消息或看到中间文件不等于前置产物已就绪。用于后续执行的产物需有明确位置与适用版本，并通过该后续任务所需的检查；若分支仍在修改它，先约定稳定交付点，避免依赖半成品或过时内容。审查进行中的工作时明确审查版本，结论仅适用于该版本。
- 等待期间发生要求变更、分支失败或依赖解除时，重新判断可推进的工作。分支超时或失败先检查状态与原因，不仅因耗时较长就复制同一任务；确需接管或重派时，先停止原执行并交接已有成果与修改权限。无法自行取得必要外部输入时，说明缺失信息及其影响，按任务约定等待或交付当前进展，避免连续有界等待变成无期限轮询。
- 按结果影响范围安排检查：局部完成先核对接口与相关行为，整体集成后再对照原始要求验收；核心逻辑或接口变化时重新检查受影响的依赖任务。

## 升级与返工

| 障碍 | 动作 |
|---|---|
| 缺少信息或证据 | 补充读取或检索；无法取得的必要信息标为受阻 |
| 工具或环境问题 | 检查输入、权限、依赖和日志，不盲目提高推理强度 |
| 明确的推理困难 | 按难点直接选择合适的推理档位 |
| 同一问题定点修正后仍失败 | 携带原始要求、失败证据和已尝试方法升级，避免重复尝试 |
| 核心方案错误 | 指定方案负责人修正，标记受影响产物并通知对应分支 |
| 局部内容或格式错误 | 原执行负责人定点修复，并复查修改部分及受影响依赖 |

审查意见必须包含具体位置、证据、影响和修改要求。按问题影响限定修改范围。修改关键含义、核心逻辑或整体方案后必须重新验收。

运行快照须先匹配随包的 `runtime-manifest.json`，部分安装或清单缺失时失败并保留源文件。运行中不调用 `--seal` 掩盖不一致；该选项仅供维护者在有意修改后重建包清单。脚本拦截常见用户、仓库和插件缓存安装目录；调用方仍须避开宿主额外配置的发现目录。摘要用于内容一致性检查，不提供权限隔离或对抗性身份认证。
