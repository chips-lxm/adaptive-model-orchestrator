# 协作与验收细则

只在任务实际需要时读取本文件。这里补充角色分工、分支交接、状态和升级规则。

## 典型职责

| 工作 | 默认配置 | 适用范围 |
|---|---|---|
| 理解需求与整理限制 | Sol · medium | 提取目标、材料、约束、交付格式与验收要求 |
| 复杂任务整体方案 | Astra · high | 确定核心方法、任务结构、依赖和验收标准 |
| 搜集与整理资料 | Luna · medium；复杂材料用 Terra · medium | 检索、提取、分类并保留来源；来源冲突或关键解释交 Sol |
| 分工与进度协调 | Sol · medium | 派发任务、跟踪状态、处理依赖；方案冲突返回 Astra |
| 代码与文件制作 | Terra · medium/high | 实现、制作并运行必要验证 |
| 内容表达与结构设计 | Sol · medium/high | 组织讲解逻辑、叙事和视觉层级 |
| 机械排版与批量修改 | Luna · medium；复杂布局用 Terra · medium | 套用既定样式并检查渲染效果 |
| 常规检查与修正 | Sol · high 审查；原执行模型修正 | 检查遗漏、报错、格式、引用与接口并定点修复 |
| 复杂任务最终验收 | Astra · medium；复杂逻辑用 high | 对照原始要求、实际成品和关键验证证据 |

这些是路由默认值，不要求每个任务执行全部步骤或为每个角色新建分支。普通任务可以合并角色。

## 分支派发与返回

派发时说明：

- 任务目标与可核对的验收标准；
- 必要原始材料、约束和来源入口；
- 可修改范围及明确边界；
- 前置依赖、接口约定与完成后的接收方。

要求分支返回：

- 实际产物、文件位置或可直接集成的结果；
- 验证方法、结果和证据；
- 未解决问题、失败证据及影响范围；
- 需要总负责人决定的事项与备选方案。

总负责人维护简洁任务清单，至少记录目标、负责人、实际模型与强度、依赖、产物位置和验证状态。状态使用：待开始、进行中、等待依赖、待检查、已完成、受阻。

## 升级与返工

| 障碍 | 动作 |
|---|---|
| 缺少信息或证据 | 补充读取或检索；无法取得的必要信息标为受阻 |
| 工具或环境问题 | 检查输入、权限、依赖和日志，不盲目提高推理强度 |
| 明确的推理困难 | 直接提高强度或升级至合适模型，无需机械地逐级尝试 |
| 同一问题定点修正后仍失败 | 携带原始要求、失败证据和已尝试方法升级，避免重复尝试 |
| 核心方案错误 | 由 Astra 修改相关方案，标记受影响产物并通知对应分支 |
| 局部内容或格式错误 | 原执行模型定点修复，并复查修改部分及受影响依赖 |

审查意见必须包含具体位置、证据、影响和修改要求。纯风格偏好不自动触发整份重写。Sol 先处理常规问题，复杂任务由 Astra 最终验收；修改关键含义、核心逻辑或整体方案后必须重新验收。
