# Independent candidate-skill forward test

Scope: candidate `github-preview/deep-project-review/SKILL.md`, its runtime/templates/entry references, and `github-preview/adaptive-model-orchestrator/SKILL.md` with its collaboration reference. Inputs were the 18 trigger and 12 workflow cases in `deep-project-review/tests/cases.json`, plus 12 migration cases in `skill-migration-2026-09-23/migration-cases.json`. This is a maintenance test of decision rules, **not** authorization to start any of the synthetic review flows. W01 alone was executed; all other rows are reasoned synthetic decisions. I did not read other agents' reports or prior expected answers/results.

The model IDs and effort values below are **routing decisions**, not claims of actual calls. No scenario subagents were spawned, so requested/effective model fields for those scenarios are respectively hypothetical/not observed. A complete real deep review would additionally need host-record proof of effective `gpt-6-astra`/`xhigh`; a child assertion alone is insufficient.

## Candidate behavior ambiguities observed

T04 exposes a difference between **semantic authorization** (“use this Skill”) and **host loading** when the optional entry is absent. The candidate text does distinguish these but does not guarantee an unconfigured natural-language request will load the skill. In production, record both states separately. T02/T03 configured-entry status in the case file is assumed for scenario reasoning only; actual host end-to-end loading was **not checked** here. All workflow cases except W01 were **synthetic**, so they do not validate live spawn configuration, conflict handling, repair loops, or delivery claims.
